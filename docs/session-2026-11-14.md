# Session 2026-11-14 — Docker database location fix

## What happened
A test Docker deployment lost its data when the container was recreated. Root
cause: the SQLite file was written to `/app/sylloge.db` (container layer), not
the `/data` volume.
- The example config ships a relative `path = "sylloge.db"`, which resolves
  against the process CWD (`/app` in the image).
- `SYLLOGE_DB` (set in the Dockerfile and compose) was never read by any code.
- `store.Open` silently creates the file, so nothing warned anyone.
- `install.sh` had the same trap: relative path, so the DB followed the launch dir.
- README claimed the DB was on the named volume; that was false.

Docs had no write-up of this before; `CLAUDE.md` only noted `SYLLOGE_DB` "is not read".

## What shipped (PR #1, branch `fix/database-path-config`, commit 9293e44)
Decision: `database.path` in `sylloge.toml` is the single DB location. No env
override; `SYLLOGE_DB` removed as dead config. No `/data` hard-coded in Go.
- `sylloge.toml.example`: guidance + worked examples (file created on first run,
  folder is NOT created, relative = launch dir, `~` not expanded, Docker uses
  `/data/sylloge.db`).
- `cmd/sylloge/main.go`: logs `database: <absolute path>` at startup.
- `install.sh`: writes an absolute path under the config dir.
- Dockerfile/compose: `SYLLOGE_DB` removed; compose comment says set
  `path = "/data/sylloge.db"`.
- README, CLAUDE.md, AGENTS.md updated; `TestLoadDatabasePath` added.
- CI (build/vet/test) passed on the PR.

## Verified / not verified
- Verified: build/vet/test; local run writes `./sylloge.db` and logs its path;
  missing parent folder fails with "no such file or directory"; `install.sh`
  config block generates an absolute path (config section only, not a full install).
- **NOT verified: any container run.** Docker was not installed in the dev
  environment.
