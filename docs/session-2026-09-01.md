# Session 2026-09-01 — v1 shipped to GitHub

## Where the project stands

**v1 is complete and public.** Repo: https://github.com/parvosub/sylloge
(MIT, owner `parvosub`). Release **v1.0.0** is published with prebuilt binaries
(linux/darwin × amd64/arm64, each with a `.sha256`) and a Docker image on GHCR
(`ghcr.io/parvosub/sylloge:latest` and `:v1.0.0`). CI runs build/vet/test on
every push and PR; tags `v*` trigger the release workflow (binaries + GHCR).

The dev server is **stopped** (nothing on :8080). The local `sylloge.db` was
wiped for a clean ship; test data lives only in git history-free commits.

## What changed this session (ship phase)

1. **TOML config file is the single source of truth** (no env fallback for
   LLM/db). New `internal/config` package: `Load(path)` + `Default()` with
   validation (provider must be `local`/`cloud`; `cloud` requires `api_key`).
   App reads `sylloge.toml` (override via `SYLLOGE_CONFIG`); `SYLLOGE_ADDR`
   still sets the listen address. `sylloge.toml.example` ships in the repo;
   the real `sylloge.toml` is gitignored (may hold API keys).
2. **Summarizer refactored to OpenAI-compatible** `/v1/chat/completions`
   (`internal/summarize/openai.go`, `OpenAICompatibleSummarizer`). Works with
   local Ollama (`http://host:11434/v1`) or any cloud OpenAI-compatible
   provider via `Bearer` auth. The old Ollama-native `/api/generate` impl was
   deleted. `Summarizer` interface unchanged.
3. **`--version` flag** in `cmd/sylloge/main.go` (`var version = "dev"`,
   overridden via `-ldflags "-X main.version=..."` in the release workflow).
4. **Private IP purged** from all tracked files and — via a fresh root commit
   (orphan branch) — from git history entirely. History is now 6 clean commits.
5. **Installer + CI/CD**: `install.sh` (OS/arch detect, downloads from
   Releases, verifies checksum, writes default config to `~/.sylloge/`);
   `.github/workflows/ci.yml` (build/vet/test) and `release.yml` (binaries +
   checksums + GHCR image, `packages: write`).
6. **Docs**: MIT `LICENSE`; portfolio README (badges, why-this-stack, config
   docs, Docker/curl installs); single `docker-compose.yml` that pulls the
   GHCR image (swap `image:` → `build: .` for source builds); README Docker
   section offers git-clone (compose) or curl-the-config (plain `docker run`)
   routes; `docs/specs/README.md` made public-facing.

## Architecture (current)

```
cmd/sylloge          entrypoint: --version flag, SYLLOGE_CONFIG/ADDR env, wiring
internal/config      TOML load + validate (database, llm, api sections)
internal/store       SQLite CRUD (classes, students, notes, summaries)
internal/summarize   Summarizer iface + OpenAI-compatible impl
internal/server      HTTP handlers/routes, markdown→flowing-prose converter
internal/web         embedded html/template sets + formatDate/sanitizeFilename
```

UI (HTMX, server-rendered): dashboard with class cards → class page with
students → student page with add-note form, Prior Notes (3 visible, older
collapsed behind a toggle), Generate Summary (spinner + toast), editable
summary box with Copy/Download, collapsible Summary History inline plus a
full history page.

Tests: table-driven across store / server / summarize / config / markdown
(`go test ./...` green; CI enforces it).

## Running locally

```sh
cp sylloge.toml.example sylloge.toml   # edit llm.api.base_url + llm.model
go run ./cmd/sylloge                    # http://localhost:8080
```

`docker compose up -d` pulls the GHCR image (needs `sylloge.toml` beside it).

## Workflow notes for resuming

- Hybrid loop: `plan` (frontier) writes a spec in `docs/specs/` → local
  `build` agent executes it → `review` audits. One spec = one step.
- Permissions (`.opencode.json`): `rm`, `git push`, `gh` prompt; everything
  else auto.
- The global pre-push security hook fires on the real-name git author and on
  `api_key` lines in config examples/tests (all empty/fake values). The owner
  has approved `SKIP_SECURITY_CHECK=1 git push` for this repo; do not commit
  real secrets.
- Modelfile at repo root is now **optional** — the system prompt lives in
  `sylloge.toml` (`llm.system_prompt`). Keep or drop it in a future pass.
